Command line tool

Interpreter scheduling for a rural clinic

Matches contract interpreters to appointments by language, modality and availability, and says why it could not match the ones it could not.

Source on GitHubPython 3, no dependencies, SQLite on disk

The problem

A clinic serving immigrant patients books a handful of contract interpreters across several languages. A missed match is a cancelled appointment, and the person who loses the visit is the one least able to reschedule it. The scheduling itself is small; the part that matters is knowing, for each appointment nobody can cover, which constraint actually failed.

Two interpreters, three appointments

One speaks Spanish and Mam and works by phone or video. One speaks Amharic and works by phone only. Three patients need Spanish, Amharic and Karen.

$ clinic_scheduler.py --db clinic.db schedule
{
  "scheduled": [
    {
      "appointment_id": 1,
      "interpreter": "A. Reyes",
      "interpreter_id": 1
    },
    {
      "appointment_id": 2,
      "interpreter": "B. Osei",
      "interpreter_id": 2
    }
  ],
  "unmatched": [
    {
      "active_interpreters": 2,
      "appointment_id": 3,
      "failed_availability": 0,
      "failed_conflict": 0,
      "failed_language": 2,
      "failed_modality": 0
    }
  ]
}

Two matched. The third is unmatched, and the diagnostic says why: failed_language: 2 means both interpreters were free and available and neither speaks Karen. A scheduler that only reported the failure would leave a coordinator guessing between a rota problem and a hiring problem. These are different problems.

What else it does

  • Weekly recurring availability per interpreter, checked against appointment times
  • Conflict detection, so nobody is booked twice
  • Confirmation dispatch through a local mail transfer agent
  • No-show recording for patients and interpreters separately
  • A monthly CSV for Title VI language-access documentation
